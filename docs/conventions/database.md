# Database Conventions

Rules for everything under **`packages/acme-db`** — the Drizzle ORM schema + migrations on
Postgres. The thin `@docs/conventions/database.md` import in
`.claude/rules/database-conventions.md` points here. The **`migration-reviewer`** subagent
audits every schema/migration change against this file before commit.

## Primary keys

Always a UUID, generated by the database. **Never auto-incrementing integers** — sequential
IDs leak row counts and break across partitions.

```ts
id: uuid("id").primaryKey().defaultRandom(),
```

## Column names

Explicit `snake_case` SQL names on every column. The TypeScript field is camelCase; the SQL
name is the string argument:

```ts
userId: text("user_id").notNull(),
organizationId: uuid("organization_id").notNull(),
```

## Timestamps

- Always `{ withTimezone: true }` — Postgres stores UTC, the app converts at the edge.
- `createdAt` on **every** table.
- `updatedAt` only on **mutable** tables, set **manually** in the repository on each write.
  Do **not** use `$onUpdateFn` — it hides write paths and surprises bulk updates.

```ts
createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
```

## Strictness & typing

- `.notNull()` on every required field.
- JSONB columns are explicitly typed with `.$type<T>()` — never an untyped `jsonb`:

```ts
metadata: jsonb("metadata").$type<SessionMetadata>().notNull().default({}),
```

## File structure

One table per concept, in a fixed order:

1. `pgEnum()` definitions at the **top of the file**.
2. The `pgTable()` definition.
3. **Relations immediately after** the table.
4. **Indexes in the table's third argument**, named `idx_<table>_<columns>`.

```ts
export const memberRole = pgEnum("member_role", ["owner", "admin", "member"]);

export const members = pgTable(
  "members",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    organizationId: uuid("organization_id").notNull(),
    role: memberRole("role").notNull().default("member"),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    idxMembersOrganization: index("idx_members_organization_id").on(table.organizationId),
  }),
);

export const membersRelations = relations(members, ({ one }) => ({
  organization: one(organizations, {
    fields: [members.organizationId],
    references: [organizations.id],
  }),
}));
```

## Migrations

- Generate SQL with `pnpm db:generate`; apply with `pnpm db:migrate`. Never hand-edit
  generated SQL — change the schema and regenerate.
- **Never add a `NOT NULL` column to an existing table without a `default`** — it fails on
  any non-empty table.
- **Column renames span releases:** add the new column → backfill/migrate data → drop the old
  one in a later release. Never rename in place.
- **Partitioned tables** (e.g. `messages` by Session) use **composite PKs** and carry **no
  DB-level FK constraints on partitions** — enforce referential integrity in the Service layer.
